# بنية الميثاق

مشروع MAUI واحد منظم حسب الوظائف، مع فصل الحسابات والبيانات عن العرض.

~~~text
Bootstrap/        تسجيل الخدمات والتنقل وتعيينات عناصر التحكم
Core/
  Abstractions/   IQuranRepository وIReadingStore وIPrayerService وIAppNavigator
  Logic/          حساب الصلاة والقبلة وتطبيع فهرس البحث، مستقل عن الواجهة
  Models/         نماذج القرآن وموضع القراءة والعلامات
Features/
  Home/           لوحة رئيسية، ملخص الصلاة والقراءة
  Quran/          قارئ ومصدر بيانات ومخزن قراءة وصوت/تفسير
  PrayerTimes/    مواقيت وموقع وإعدادات حساب
  Qibla/          بوصلة مرسومة باستخدام GraphicsView
  Azkar/          مستودع أذكار وواجهة عدادات
  Tasbeeh/        مسبحة محلية
  Settings/       إعدادات ومصادر واستيراد وتصدير
Shared/Controls/  Ui: ألوان وخطوط وعناصر مشتركة
Resources/Raw/    قرآن ومصادر وتراخيص وأذكار
tests/            فحوصات حسابية وبيانات مستقلة عن MAUI
~~~

أسماء namespaces القديمة للواجهات باقية لتوافق x:Class. ملفات XAML هي جذور الصفحات؛ يُبنى محتواها بكود C# داخل مجلد Views. توجد نماذج عرض تفاعلية صغيرة VerseItem وDhikrRow باستخدام MVVM Toolkit. خدمات التحميل والتخزين والحساب منفصلة عن بناء العناصر.

لا تستخدم هذه النسخة صورًا أو خدمة ويب لقراءة القرآن الأساسي. التحميل الأول للبيانات المحلي Lazy<Task>، وفهرس البحث مشتق مستقل. لا يوجد Result/Wait على مسار تحميل القرآن. أحداث الواجهة فقط async void مع معالجة أخطاء؛ الأعمال الملغاة عند مغادرة الشاشة تُلغى بواسطة CancellationToken.

الاحتفاظ بالمؤقتات والحساسات مقيد بدورة حياة الصفحة. الموقع لا يُطلب عند تشغيل التطبيق تلقائيًا؛ يحصل عليه المستخدم من زر صريح، ويمكن إدخاله يدويًا.

لا توجد قاعدة SQLite أو حزم Akavache؛ حفظ الإعدادات والعلامات في Preferences، والصوت والتفسير داخل مساحة التطبيق. قد يلزم نقل العلامات إلى ملف/قاعدة مخصصة إذا توسع حجم الملاحظات كثيرًا.

التنقل يستخدم FlyoutPage وNavigationPage مع IAppNavigator، وتُحفظ حالة كل قسم أثناء التنقل. يقرأ مستودع القرآن JSON كمورد مضمّن مستقل عن خدمات MAUI، ولذلك تختبره فحوصات Core مباشرة. إعدادات Debug تستخدم معرّف com.companyname.almithaq.dev لتمييز نسخة التجربة عن Release. ملف التوقيع المحلي للتجربة داخل .local مستبعد من Git ولا يُستخدم لتوقيع إصدار المتجر.

تغليف Android يستخدم تضمين كل تجميعة في DSO مستقل مع تعطيل Assembly Store وضغط التجميعات، بعد رصد تعليق التحميل بالتهيئة السابقة ونجاح التحميل بالإعداد الجديد على المحاكي. يُستخدم Mono، ولا توجد إعدادات CoreCLR التجريبية في المشروع. زاد حجم Debug؛ يلزم قياس Release المحسّن قبل النشر.
