# الميثاق

تطبيق ديني باستخدام .NET MAUI و.NET 10. الواجهة عربية من اليمين إلى اليسار، والبيانات الأساسية محلية دون حساب إلزامي.

**حالة التطوير: نسخة للتجربة.** أُصلح تعليق تحميل القرآن على Android، وأكد المستخدم نجاح البحث. أكد المستخدم تشغيل الصوت. أُعيد تصميم القارئ بأيقونات وتحكم في التقدم ومتابعة اختيارية للآية؛ التحديث قيد تجربة الجهاز؛ التفاصيل في [حالة التحقق](docs/UPGRADE.ar.md).

## الميزات المضافة إلى الكود

- قرآن عثماني كامل محليًا: 114 سورة و6236 آية، مع خط Amiri Quran.
- عرض حسب السورة أو الصفحة أو الجزء، وانتقال مباشر إلى سورة:آية.
- بحث يتجاهل التشكيل في فهرس منفصل، دون تعديل النص المعروض.
- حفظ موضع القراءة بالتمرير، وعلامات وملاحظات، ونسخ ومشاركة الآية ومرجعها.
- حجم خط قابل للتعديل وأوضاع ورقي وفاتح وليلي للقارئ، وإخفاء الآية للحفظ.
- التفسير الميسر عند الطلب مع حفظ محلي للنصوص المفتوحة.
- تلاوة آية بآية: العفاسي والحصري والمنشاوي، متابعة وتكرار آية أو مقطع، وتنزيل السورة مع إلغاء واستكمال لاحق للملفات الناقصة.
- مواقيت اليوم أو تاريخ مختار، وصلاة قادمة، وطرق حساب ومذهب العصر وتصحيح بالدقائق وإعداد رمضان لأم القرى.
- قبلة محسوبة محليًا، وبوصلة مع تصحيح الانحراف المغناطيسي على Android.
- أذكار صباح ومساء ونوم وبعد الصلاة: مصادر، عدادات، تقدم يومي ومفضلة وبحث.
- مسبحة مع هدف شخصي، حفظ العداد، إحصاء يومي، وتراجع عن الضغطة.
- إعدادات الموقع اليدوي ومساحة الصوت وتصدير/استيراد العلامات.

## التشغيل

يتطلب Android 8.0 / API 26 أو أحدث بسبب مكون الصوت الحالي. يوجد إعدادات iOS وMacCatalyst وWindows في المشروع؛ يجب بناء هذه الأهداف واختبارها على بيئاتها قبل إصدارها.

~~~powershell
dotnet restore AlMithaq.csproj -p:TargetFrameworks=net10.0-android
dotnet build AlMithaq.csproj -f net10.0-android -p:EmbedAssembliesIntoApk=true
dotnet run --project tests/AlMithaq.CoreChecks/AlMithaq.CoreChecks.csproj
~~~

## التشغيل على iPhone من زر Run في VS Code

أُضيف إعداد `AlMithaq — iOS` داخل `.vscode/launch.json` لبناء نسخة Debug وتشغيلها على جهاز iOS المختار.

### تجهيز أدوات التطوير مرة واحدة

ثبّت Xcode وافتحه لإكمال إعداداته. ثبّت إضافة **.NET MAUI** من Microsoft في VS Code. من Terminal داخل مجلد المشروع نفّذ:

~~~sh
sudo dotnet workload restore AlMithaq.csproj
~~~

المشروع يستخدم .NET SDK ‏`10.0.400` عبر `global.json` دون تثبيت إصدار workload بعينه. ثبّت SDK بهذا الإصدار على أجهزة التطوير. سيطلب أمر استعادة الأدوات كلمة مرور المدير في Terminal. يجب أن يتوافق إصدار أدوات iOS مع Xcode؛ الأدوات `27.1.10018` المثبتة حاليًا تتطلب Xcode ‏27.1، ولا تعمل مع Xcode ‏26.3. استعادة الأدوات وحدها لا تعالج عدم التوافق؛ يلزم تثبيت Xcode المطلوب أو اختيار أدوات iOS متوافقة مع Xcode الحالي. وجود `maui-ios` في قائمة workloads وحده لا يكفي إذا كان البناء يعرض `NETSDK1147` ويطلب `ios`.

### إبقاء Xcode 26.3 مع SDK ‏10.0.400

لتثبيت أدوات iOS المتوافقة دون تحديث Xcode أو تغيير SDK، نفّذ على الماك من مجلد المشروع:

~~~sh
sudo dotnet workload install ios --from-rollback-file tools/ios-xcode26.3.rollback.json
~~~

هذا يختار manifest ‏iOS بالإصدار `26.2.10197`، ويحوّل إدارة workloads على هذا الماك إلى وضع manifests. يتطلب صلاحية المدير وتنزيل أدوات iOS الناقصة. لا تنفّذ أمر rollback على Windows. بعد اكتماله نفّذ `Developer: Reload Window` في VS Code وأعد التشغيل. لا تستخدم `dotnet workload update` دون ملف rollback إذا أردت الاحتفاظ بهذا الإصدار.

يتضمن المشروع استثناءً لفحص تطابق Xcode في Debug فقط عند استخدام أدوات iOS ‏26.2.10197 مع Xcode ‏26.3، لأن Xcode ‏26.3 يحتوي SDK ‏iOS 26.2. لا ينطبق الاستثناء على Release أو Android أو أي زوج آخر من الإصدارات.


### المحاكي

1. افتح مجلد المشروع في VS Code ثم نفّذ `Developer: Reload Window` بعد تثبيت الأدوات.
2. من لوحة الأوامر (`Cmd+Shift+P`) اختر `.NET MAUI: Select Startup Device`، ثم اختر محاكي iPhone المتاح. يمكن اختيار الجهاز أيضًا من رمز `{ }` في شريط الحالة
3. من **Run and Debug** اختر `AlMithaq — iOS` واضغط ▶ أو `F5`.

إذا لم يظهر محاكي، ثبّت iOS Simulator من إعدادات Xcode > Components. لا يحتاج المحاكي شهادة توقيع تطوير.

### الآيفون بالكابل

1. وصّل الآيفون بالـ USB وافتح قفله، ووافق على **Trust This Computer**.
2. فعّل **Developer Mode** من Settings > Privacy & Security على الآيفون، وأكمل إعادة التشغيل إن طُلبت.
3. أضف حساب Apple في Xcode > Settings > Accounts، وتأكد أن الجهاز ظاهر ومقترن في Window > Devices and Simulators.
4. جهّز شهادة **Apple Development** وملف provisioning خاصًا بالتطوير يشمل الجهاز ومعرّف التطبيق `com.companyname.almithaq`. يمكن استخدام Personal Team إذا كان مناسبًا لحسابك. وجود الشهادة وحدها لا يكفي؛ يجب أن يطابق ملف provisioning الجهاز ومعرّف التطبيق.
5. اختر الآيفون من `.NET MAUI: Select Startup Device`، ثم اضغط ▶ أو `F5` على إعداد `AlMithaq — iOS` نفسه.

لم يُثبّت إعداد التشغيل معرّف محاكي أو شهادة تخص جهازًا بعينه، حتى يمكن التبديل بين الأجهزة من قائمة MAUI.

## إصلاحات واجهة iOS

على iOS فقط، يستخدم التطبيق متحكم تنقل واحدًا وقائمة تظهر فوق الصفحة من اليمين، مع أزرار قائمة ورجوع ثابتة. يبقى مسار FlyoutPage الأصلي على Android كما هو. يستخدم قارئ المصحف ربط JavaScript خاصًا بـ WebKit مع فحص اكتمال تحميل المستند.

في Run and Debug اختر `AlMithaq — iPhone USB` للآيفون XR المتصل، أو `AlMithaq — iPhone Simulator` للمحاكي. إعداد USB يحدد معرّف الآيفون الحالي واتصال USB صراحة؛ عند استخدام آيفون آخر غيّر `device` في `.vscode/launch.json` إلى معرّف الجهاز الجديد أو استخدم إعداد `AlMithaq — iOS` واختيار الجهاز من MAUI.

### صوت إشعارات iOS

صوت القرآن ومعاينة الأصوات صوت وسائط، أما تنبيهات الأذان والصلاة على النبي والورد فتتبع إعدادات إشعارات iOS ومستوى الرنين والتنبيهات والوضع الصامت والتركيز. تفعيل إذن ظهور الإشعارات وحده لا يضمن تفعيل Sounds. اختبارات الأذان والصلاة على النبي تتحقق من إذن الصوت، وتعرض فتح إعدادات التطبيق عند تعطيله. شريط مستوى الصوت داخل التطبيق يضبط المعاينة على iOS، ولا يغيّر مستوى صوت إشعار النظام. يستخدم إشعار الأذان مقطعًا أقل من ٣٠ ثانية وفق حد iOS للأصوات المخصصة.

عند الضغط على إشعار الأذان في iOS، يفتح التطبيق إعدادات الأذان ويستكمل التسجيل الكامل بالصوت الذي استُخدم في الإشعار. المقطع المرفق طوله ٢٩٫٨ ثانية؛ يحسب التطبيق نقطة الاستكمال من وقت وصول الإشعار إلى وقت الضغط عليه بحد أقصى ٢٩٫٨ ثانية. هذه نقطة تقديرية لأن iOS لا يتيح قراءة موضع تشغيل صوت الإشعار الفعلي. يمكن إيقافه بزر إيقاف المعاينة. إذا بدأ التطبيق من شاشة الإطلاق تُحفظ نية الفتح إلى أن تصبح الواجهة جاهزة. يظل صوت الإشعار نفسه مقطعًا قصيرًا، ولا يَعِد التطبيق بتشغيل الأذان الكامل تلقائيًا في الخلفية.

إذا انقطع صوت إشعار iOS عند اختفاء البانر المؤقت، جرّب Settings > Notifications > AlMithaq > Banner Style > Persistent. طول ملف الصوت لا يضمن استمرار تشغيله إذا أوقف iOS صوت البانر. لا يستطيع التطبيق تغيير نمط البانر نيابة عن المستخدم.

### سحب المشروع على Windows

`global.json` يحدد الحد الأدنى .NET SDK ‏10.0.400 مع `rollForward: latestPatch`، فيقبل 10.0.401 وما بعده ضمن سلسلة 10.0.4xx على Windows والماك. إعداد `AlMithaq — Android` في VS Code مرتبط بمهمة بناء Android مستقلة؛ إعدادات iPhone مرتبطة بمهمة iOS. لم يتغير ملف المشروع المستهدف أو حزم Android أو أصواته. تعديل السلوك المشترك المقصود هو استمرار تلاوة القرآن عند إغلاق البحث أو مسح نصه.

### تنبيه تحديث App Store على iOS

في النسخة المنشورة على App Store، يفحص التطبيق عند فتحه والعودة إليه توفر إصدار أحدث، بحد أقصى فحص كل ١٠ دقائق. يظهر تنبيه «تحديث الآن / لاحقًا» مرة لكل إصدار خلال جلسة التشغيل، ويفتح «تحديث الآن» صفحة التطبيق في App Store. يستخرج التطبيق بيانات المتجر من معرّف الحزمة دون الحاجة إلى وضع رقم App Store يدويًا، ويستخدم بلد الجهاز في طلب البحث. لا يظهر التنبيه إذا لم يُنشر التطبيق بعد، أو عند انقطاع الإنترنت، أو إذا احتاج التحديث نظام iOS أحدث من الجهاز. التثبيت والتحديث يتمان عبر App Store.

الفحص معطّل في Debug والمحاكي ونسخ TestFlight ذات إيصال sandbox؛ يخص النسخ العامة من App Store. لا يغيّر آلية تحديث Android.

اختبارات مقارنة الإصدار وتحليل رد المتجر:

~~~sh
dotnet run --project tests/AlMithaq.AppStoreChecks/AlMithaq.AppStoreChecks.csproj
~~~
